# CHRONOS v0.1: минимальная рабочая машина исторического анализа

Прототип, а не универсальный предсказатель будущего. Он использует **реальные годовые временные ряды**, хранит источник данных, находит исторические аналоги, составляет три описательных сценария и проводит **исторический backtest**. Отдельно хранит исторические события и **явно маркированные** гипотезы о связи между ними.

## Требования

- Python 3.10 или новее.
- Библиотеки устанавливать не нужно: только стандартная библиотека Python.
- Интернет нужен **только** для загрузки настоящих данных командой `fetch`.

## 1. Запуск без интернета: тест механизма

Открой терминал в папке проекта:

```bash
python chronos.py --db chronos.sqlite demo
python chronos.py --db chronos.sqlite analyze --indicator DEMO_SYNTHETIC_INDEX --entity "Synthetic World" --horizon 10 --backtest
```

`DEMO_SYNTHETIC_INDEX` является **выдуманным тестовым набором**. Полученные из него прогнозы не имеют никакого отношения к реальному будущему.

## 2. Настоящие исторические данные

```bash
python chronos.py --db chronos.sqlite fetch --slug life-expectancy --entity World
python chronos.py --db chronos.sqlite analyze --indicator life-expectancy --entity World --horizon 10 --backtest --json-out report.json
```

Если у графика отсутствует агрегат `World`, используй страну, присутствующую в данных, например `United States`. Поиск подходящих графиков: https://ourworldindata.org/data

Встроенный загрузчик использует **официальный** OWID Grapher CSV (`https://ourworldindata.org/grapher/{slug}.csv`). Документация: https://docs.owid.io/projects/etl/api/chart-api/ . При нескольких колонках выбирает первую, либо укажи точное имя через `--column`.

Можно импортировать собственные показатели. CSV должен иметь колонки `Year,Value`:

```bash
python chronos.py --db chronos.sqlite import-csv --file population.csv --indicator population --entity World --source-url "https://example.org/original-source"
python chronos.py --db chronos.sqlite analyze --indicator population --entity World --horizon 5 --backtest
```

Не подставляй фиктивный URL в настоящие исследования. Скрипт сохраняет переданное значение, **не проверяет** правдоподобность пользовательского источника.

## 3. Исторические события и цепочки гипотез

```bash
python chronos.py --db chronos.sqlite import-events --file events_example.csv
python chronos.py --db chronos.sqlite import-claims --file claims_example.csv
python chronos.py --db chronos.sqlite events
```

События и связи хранятся в SQLite. Примерные связи имеют статус `analogy` или `hypothesis`, а не доказанный факт. Импорт `documented` требует ссылку, но **сама ссылка не доказывает причинность**. Этот прототип НЕ осуществляет автоматического обнаружения причинных эффектов и НЕ извлекает события из всего интернета.

## 4. Как работает прогноз

- Берём несколько последних последовательных лет показателя.
- Ищем похожие шаблоны годовых темпов роста в его прошлом.
- Для каждого исторического аналога смотрим, каким оказалось изменение в последующие `horizon` лет. Аналоги берутся **только там, где эти будущие годы уже были известны на момент моделируемого прогноза**.
- Три сценария: 10-й, 50-й и 90-й процентили наблюдаемых исходов ближайших аналогов; это **не** вероятностный интервал 80% и **не** доказательство причинности.
- Сравниваем среднюю абсолютную ошибку (MAE) и процентную ошибку (MAPE) модели и примитивного прогноза-продолжения текущего темпа роста на исторических окнах.
- Не следует доверять сценарию, если модель не обходит этот простой baseline при backtesting на действительно отложенной выборке. Даже хорошая историческая точность не гарантирует будущую.

## Ограничения

1. Только **одномерные положительные годовые показатели**. Многомерной глобальной модели пока нет.
2. Ближайшие исторические аналоги создают **описательные условные сценарии**, а не научно подтверждённый прогноз.
3. Пропуски лет могут ограничить доступные интервалы анализа.
4. Серии, которые были позднее пересмотрены, создают риск **ревизионной утечки** в backtesting: исторический учёный мог не иметь сегодняшних версий показателей. Для научной проверки потребуются архивные версии данных.
5. Пока нет автоматического загрузчика Seshat, GDELT, World Bank, онтологии, нейросетевого извлечения событий, причинной идентификации, калибровки вероятностей или нормального веб-интерфейса.
6. Автоматически загружаемые данные должны использоваться с учётом лицензии и ограничений источника.

## Дорожная карта полноценной системы

**v0.2:** загрузчики World Bank, Maddison, Seshat, GDELT; единые метаданные, качество и версии данных.

**v0.3:** граф утверждений `событие -> механизм -> следствие` с цитированием документов, явными датами и оценкой надёжности.

**v0.4:** многомерные модели (демография, капитал, технологии, энергия, институты), интервенции и контроль смешивающих факторов.

**v0.5:** строгий walk-forward backtesting, сравнение с baseline и экспертными прогнозами, калибровка неопределённости.

**v1.0:** интерактивный исследовательский интерфейс и несколько конкурирующих сценариев развития мира.

## Что важно

CHRONOS не должен «обучаться на истории» так, чтобы задним числом придумывать убедительные объяснения. Любую гипотезу сначала формулируем, затем проверяем на данных, которых она не видела. **Подтверждение исторической закономерности — отдельная задача от качественного прогнозирования будущего.**
